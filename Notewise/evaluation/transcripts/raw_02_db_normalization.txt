Welcome back students today we discuss database normalisation up to boyce codd normal form or B C N F. Why normalise to eliminate insertion deletion and update anomalies and minimise redundant data storage. In first normal form or one N F every column contains atomic values. In second normal form or two N F we are already in one N F and there is no partial dependency non prime attributes must depend on the whole candidate key. In third normal form or three N F for every functional dependency X determines Y either X is a super key or Y is a prime attribute. B C N F is strictly for every non trivial functional dependency X determines Y X MUST be a super key. Every relation in B C N F is in three N F but not every three N F relation is in B C N F.
